### 技术背景：大规模 Agent 推理共享资源与访问竞争
**大规模集群让计算实例可以按需访问共享资源**

随着模型、上下文和并发规模扩大，缓存和模型数据可以分布在 Host 内存或 NPU 显存中，由多个计算实例共同使用。池化可以减少重复存储，也能让各实例按需取数。多个实例即使访问的是不同数据，只要数据落在同一个池节点，仍会共享它的内存通道和 UB 出口。多个资源池的流量也可能在同一条交换链路上汇聚。 [昇腾 KV Cache 池文档](https://docs.vllm.ai/projects/ascend/en/main/user_guide/feature_guide/kv_cache_pool_ascend_store.html)

**Agent 多轮推理让共享访问反复发生**

一个会话在模型推理和工具调用之间多次切换。工具返回时，当前实例可能需要从其他实例或共享池恢复历史 KV。并发下，有的会话只差最后一批数据就能继续，有的会话还在大批回读，资源池也可能同时服务预取和回填。池化省下了存储空间和重算，但热点端点的排队会拖慢会话恢复。若关键流量持续优先，大批搬运也可能失去稳定带宽。

**核心问题：**

**当多个实例并发访问共享资源池时，UB 能否在实际争用的端点和路径上细分带宽，让关键批次按时完成，同时让大批传输稳定推进。**

### **技术方向：**
1. **多资源池访问的负载分布与热点分流：（数据从哪个端点取）**
+ 问题：多个实例访问的数据不同，数据放置和请求选源会让流量集中到少数池节点。热节点的 UB 出口已饱和，其他节点的存储和带宽仍有余量。
+ 价值：把可分散的读取流量分到多个池节点，降低最繁忙节点的排队时间，让新增池节点的容量和带宽都能支撑更多并发访问。
2. **共享端点的细粒度带宽分配：（固定端点带宽如何分配）**
+ 问题： 关键小批读取和大批搬运共用同一个端口或内存通道时，已经提交的大批传输会拖住后到的关键批次。高并发下，若关键流量一直优先，大批搬运又可能拿不到稳定带宽。
+ 价值：在同一端点控制关键批次的尾延迟，同时维持大批传输的有效吞吐。
3. **跨节点共享路径的拥塞感知与带宽协调：（多端点共用链路带宽如何分配）**
+ 问题：多组计算实例和池节点分别通信，各自端口都还有余量，但它们的流量可能在同一段交换链路上叠加，合起来超过这段链路的承载能力。
+ 价值：减少跨节点汇聚造成的排队，避免一段热点链路同时拖慢多组原本独立的访问。随着池节点和实例增多，集群仍能在相同链路配置下承载更多同时满足时延和吞吐目标的负载。

### **预期结果**
**在 A5 集群规模扩大后，让共享 UB 访问池化资源的关键小批传输按时完成，大批传输持续跑满它带宽；在集群承受最大负载场景下，同时满足系统低时延与高吞吐。**

+ **池节点 **减少热点出口排队，提高可分流读取的并发承载能力。
+ **共享端点 **降低关键批次的 P99 完成时间，同时保持大批传输的目标吞吐。
+ **共享链路 **减少多节点汇聚造成的拥塞，使两类流量在更多实例和池节点并发时仍能同时达标。

### 技术可落地场景
+ **EPD 与历史 KV 回流**验证**不同来源汇入同一个接收端**。E→P 的特征和 D→P 的历史 KV 经不同连接进入 P，关键阶段的数据更早到齐，同时保持大批回流的进度。
+ **Engram 共享表**验证**多读者打到同一个池节点出口**。Prefill 批量查表，与 Decode 当轮只差几行的读取竞争。当步查表尾延迟下降，同时保持批量查表吞吐。
